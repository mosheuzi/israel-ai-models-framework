# הגדרת מרחב ההחלטה

## הבעיה

דיון על מודל ישראלי נוטה להציג באותה רשימה שירות API מנוהל; מודל פתוח; מנגנון RAG לאחזור ידע; תהליך fine-tuning להתאמת מודל; שותפות; ואימון מודל. הרשימה מערבבת החלטות מסוגים שונים ולכן אינה מאפשרת השוואה עקבית.

לפני הערכת השליטה יש לתאר כל חלופה בשלושה צירים נפרדים:

1. כיצד מתקבלת יכולת המודל.
2. היכן ובשליטת מי היא מופעלת.
3. כיצד היא מותאמת לשימוש.

אחזור ידע באמצעות RAG והתאמת מודל באמצעות fine-tuning הם שיטות התאמה. שותפות היא דרך מימוש ומשילות. מודל ייעודי מתאר היקף ומטרה. הם אינם חלופות ריבונות מקבילות ל-API, למשקולות הניתנות להפעלה עצמאית או לאימון מודל בסיס.

## ציר 1: כיצד מתקבלת יכולת המודל

| משפחת חלופה | מה מתקבל | מה נשאר בשליטת גורם חיצוני | שאלת השליטה המרכזית |
|---|---|---|---|
| שירות מודל מנוהל, בדרך כלל API | גישה ליכולת של מודל המופעל בידי ספק | משקולות, תפעול ושינויים במודל | האם החוזה, הקיבולת, הרציפות ויכולת המעבר מספקים? |
| משקולות הניתנות להפעלה עצמאית | זכות להחזיק ולהריץ את המודל, בכפוף לרישיון | ארכיטקטורת המקור, provenance ולעיתים רכיבי תוכנה | האם ניתן להפעיל, לשנות ולתחזק ללא תלות שוטפת בספק? |
| פיתוח מודל בשליטה ישראלית | משקולות ותהליך פיתוח הנמצאים בשליטת הגורם הישראלי | תשומות חיצוניות שעדיין נדרשות, כגון מאיצים, תוכנה וידע | אילו פערים מחייבים פיתוח, ומה נשאר תלוי בשרשרת חיצונית? |
| תהליך שאינו מבוסס AI | חלופה ידנית, דטרמיניסטית או ארגונית | לפי התהליך | האם שימוש ב-AI נחוץ מלכתחילה? |

### שירות באמצעות API ותוכניות התחייבות

קיבולת שמורה, המכונה Provisioned Throughput, מופע ייעודי או התחייבות ארוכת טווח אינם משפחה נפרדת. הם תצורות בתוך שירות מנוהל. הם עשויים לשפר זמינות, מחיר, ביצועים והגנות חוזיות, אך אינם מעבירים בהכרח שליטה במשקולות או בתפעול לישראל.

יש לבדוק:

- התחייבות לקיבולת, זמינות ומחיר.
- מיקום העיבוד, הלוגים והתמיכה.
- שינוי חד-צדדי במודל או בתנאי השירות.
- תנאי סיום, אחריות והודעה מוקדמת.
- אפשרות לייצא נתונים, התאמות ותוצרים.
- תלות של השירות בתשתיות מחוץ לישראל.

## ציר 2: תצורת ההרצה

גישה למשקולות אינה קובעת לבדה את רמת השליטה. אותו מודל יכול לפעול בתצורות שונות:

| תצורת הרצה | משמעות |
|---|---|
| שירות משותף המנוהל בידי ספק | הספק שולט במודל ובתפעול |
| שירות ייעודי המנוהל בידי ספק | בידוד וקיבולת טובים יותר, אך השליטה התפעולית נשארת אצל הספק |
| הרצה בחשבון ענן בשליטת הארגון מחוץ לישראל | שליטה תפעולית גבוהה יותר, תחת תשתית ותחום שיפוט חיצוניים |
| הרצה באזור ענן בישראל | מיקום מקומי, אך יש לבחון מי מפעיל, מי יכול להפסיק שירות ובאילו תשומות האזור תלוי |
| הרצה בחוות שרתים מסחרית בישראל | שליטה מקומית אפשרית יותר, בכפוף לבעלות, תפעול ושרשרת האספקה |
| תשתית ממשלתית, לאומית או מבודדת בישראל | שליטה תפעולית גבוהה, לצד עלות, כוח אדם ותלות בחומרה ובתוכנה חיצוניות |

לכן המונח self-hosted אינו תשובה מספקת. יש לציין מי מחזיק במשקולות, מי מפעיל את התשתית, היכן היא נמצאת, מי מוסמך לגשת אליה והאם היא יכולה לפעול בעת ניתוק מספק חיצוני.

## ציר 3: שיטת ההתאמה

שיטות אלה יכולות להופיע בתוך כמה משפחות חלופה ותצורות הרצה:

| שיטה | מה היא משנה | מה היא אינה פותרת לבדה |
|---|---|---|
| התאמה באמצעות הנחיות והגדרות מערכת, prompting | אופן השימוש במודל | ידע חסר, שליטה במשקולות או תלות בספק |
| אחזור ידע והקשר באמצעות RAG | ידע והקשר הנשלפים בזמן הרצה | יכולת בסיסית, רישיון, זמינות המודל או שליטה בתשתית |
| התאמת התנהגות באמצעות fine-tuning | התנהגות או ביצועים במשימות מוגדרות | מקור המודל, provenance, מגבלות ארכיטקטורה ותלות במודל הבסיס |
| המשך אימון של מודל קיים, continued pre-training | הידע והייצוגים של מודל קיים באמצעות אימון נוסף | התלות בארכיטקטורה ובבסיס שממנו התחיל האימון |
| אימון מודל בסיס מאפס | יצירת משקולות בסיס חדשות מתהליך אימון רחב | תלות במחשוב, מאיצים, תוכנה, אנרגיה, דאטה וכוח אדם |

התאמת מודל באמצעות fine-tuning אינה אימון מאפס. המשך אימון של מודל קיים, continued pre-training, הוא מצב ביניים מהותי: הוא עשוי ליצור שליטה ויכולת רחבות יותר מ-fine-tuning, אך עדיין מתחיל ממודל קיים.

## כאשר נשקל אימון מודל בסיס מאפס

אין להעריך רק את עלות ריצת האימון. יש לבחון לפחות:

- זכויות, איכות, ייצוג ותיעוד המקור, provenance, של הקורפוסים.
- הכנת נתונים, סינון, הסרת כפילויות, deduplication, ובקרת איכות.
- מאיצים, קיבולת, אנרגיה, אחסון ורשת.
- קוד אימון, נקודות שחזור, checkpoints, והתאוששות מכשל.
- צוות מחקר, הנדסה, תפעול מודלים, MLOps, ותחזוקה.
- תהליכי הערכה, evaluation, בעברית, ערבית ובהקשר הישראלי.
- אימון משלים, post-training, וכן בדיקות בטיחות, סייבר וצוות אדום.
- תשתית להרצת המודל, inference, ולהפצתו בקנה המידה הנדרש.
- עדכון, אימון חוזר וקצב התיישנות מול מודלים אחרים.
- רישוי, הפצה, אחריות משפטית ועלות חלופית.
- התלויות החיצוניות שנותרות גם לאחר השלמת האימון.

## יחידת ההשוואה

חלופה מלאה היא צירוף של שלוש החלטות, לדוגמה:

> משקולות הניתנות להפעלה עצמאית + הרצה באזור ענן בישראל + אחזור ידע באמצעות RAG והתאמת מודל באמצעות fine-tuning

או:

> שירות ייעודי באמצעות API עם קיבולת שמורה + עיבוד באזור ישראלי + אחזור ידע באמצעות RAG ממאגר ממשלתי

רק חלופות מלאות כאלה ניתנות להשוואה מבחינת איכות, עלות, זמן, שליטה, חוסן ותלות.
